# 0014. Give the agents their own Node, and wrap their commands

**Status:** Accepted · **Date:** 2026-08-06

## The problem

Claude Code and Pi are Node.js programs and need a reasonably recent Node (22 or
newer). Your project might have no Node at all, or an older one that your code
depends on.

We must not change your project's Node. If your app needs Node 18, upgrading it
behind your back to install a coding agent would be an unforgivable thing for an
add-on to do.

## What we decided

**Check first, and only install our own copy if we have to.**

```sh
node -p 'process.versions.node.split(".")[0]'   # major version
```

- Node 22 or newer already present → use it, install nothing.
- Otherwise → download Node into `/opt/agentified/node`, which is ours alone
  and not on anyone's `PATH`.

You can turn the second half off with `"installNodeIfMissing": false`, in which
case the build fails with a clear message rather than installing anything.

The download is checked against the official `SHASUMS256.txt` published
alongside it, so a corrupted or tampered download fails the build instead of
being silently installed.

## The second problem: how the commands find Node

npm installs command-line tools as small scripts starting with a line like:

```
#!/usr/bin/env node
```

That means "run this with whatever `node` is first on the `PATH`". Which is
precisely the wrong behaviour here — we installed a private Node *because* the
one on the `PATH` is unsuitable or absent. Symlinking the agent's command into
`/usr/local/bin` would give you a command that runs under your project's old
Node, or fails with "node: not found".

So instead of a symlink, each agent command gets a small **wrapper**:

```sh
#!/bin/sh
# Generated by agentified: pins the agent to its own Node runtime.
PATH="/opt/agentified/node/bin:$PATH"; export PATH
exec "/opt/agentified/npm/lib/node_modules/.../claude" "$@"
```

Now `claude` always runs under the Node it was installed with, and your `node`
command is still your Node. The two never meet.

When the image already had a suitable Node, the wrapper is generated without the
`PATH` line — the agent uses the system Node, which is fine, because that's what
"suitable" meant.

## What it costs

- **Disk space.** A private Node is roughly 50 MB. Only when needed.
- **The agent's Node won't be updated by your project's tooling.** If you
  upgrade your project to Node 24, the agent keeps using its own copy until the
  Feature is rebuilt. That's the intended isolation, but it does mean the agent
  can lag.
- **A pinned version to maintain.** The Node version is a constant in
  `install.sh` and someone has to bump it occasionally.

## How it's tested

The `verify` suite runs `claude --version` and `pi --version` **as the workspace
user, through a login shell** — the same path a human would take. If the wrapper
were wrong, or the private Node weren't found, this fails.

The `claude_and_pi` scenario installs both agents at once and checks both are on
the `PATH` and both run, which also confirms the two don't interfere with each
other.
